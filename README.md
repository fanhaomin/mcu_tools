# Embedded Debug (STM32)

STM32 一体化插件：工程识别 · CMake 编译 · ST-LINK 烧录 · 在线调试 · 实时监控。

> 原「Auto CMake Flash」——扩展标识不变，老版本直接升级，设置与数据无需迁移。

## 准备环境

| 组件 | 说明 |
| --- | --- |
| VS Code 或 Trae | 1.85 及以上 |
| [STM32CubeCLT](https://www.st.com/en/development-tools/stm32cubeclt.html) | 一次安装即含 CMake、Ninja、GNU-ARM、STM32CubeProgrammer |
| ST-LINK 探头 + 目标板 | 烧录与调试用 |
| 「Embedded Debug (probe-rs)」扩展 | 调试用，第一次点调试时按提示安装即可 |

## 安装

```powershell
# VS Code
code --install-extension auto-cmake-flash-<版本>.vsix
# Trae CN（应用运行中 CLI 可能静默失败，先关闭 Trae）
& "$env:LOCALAPPDATA\Programs\Trae CN\bin\trae-cn.cmd" --install-extension auto-cmake-flash-<版本>.vsix
```

安装后重载窗口，活动栏出现芯片图标。

## 六步上手

1. **打开工程**：含 `CMakeLists.txt` 的 STM32 工程（CubeMX 导出的 CMake 工程直接可用）。
2. **扫描工程**：活动栏点插件图标 → **扫描工程**。自动识别工程结构与 MCU 型号；型号不确定时会提示手动选择。
3. **检测开发环境**：点 **检测开发环境**。装了 STM32CubeCLT 通常全部自动找到；缺什么就在设置里填对应路径。
4. **编译工程**：点 **编译工程**。报错会写入「问题」面板，点击跳转到出错行。
5. **烧录**：连接 ST-LINK → 点 **编译并烧录** → 弹出确认窗口（工程 / MCU / 探头 / 固件信息）核对无误 → **确认烧录**。
6. **调试**：点 **编译并调试**，自动停在 `main`；底栏出现「**调试器**」面板（不开调试时隐藏）。

## 调试面板怎么用

### 变量监控
- 输入框填变量名回车即可：支持 `test_array[1]`、`cfg.speed`、`sa[2].speed` 这类写法。
- 也可以在代码里**选中变量右键 →「添加到变量监控」**；或点「浏览」搜索全部全局/静态变量。
- 打断点停下时，当前函数的**局部变量自动捕获**。
- 点某个值可以直接修改回写；右键可切换显示进制（十进制 / 十六进制 / 二进制 / 字符 / 同时显示）。
- 数组、结构体点箭头逐层展开；被优化掉的变量会标红「不在 ELF 中」。

### 波形
- 点「**变量 ▾**」勾选要画曲线的变量（整数 / 浮点 / 布尔）。
- **滚轮缩放**时间窗，**拖动平移**，**双击回到实时**；鼠标悬停显示十字线和各变量的值。
- 工具栏可切时间窗（10s / 30s / 60s / 全部）、暂停、清空、锁定 Y 轴。

### 数组
- 变量监控里的二维及以上数组自动出现在这里：矩阵铺开，**每格显示数值**，颜色 = 数组内最小→最大。
- 多维数组（如 `2×3×4`）按切片全部铺开，切片多时用 **‹ ›** 翻页；悬停显示元素下标和值。
- 「数组 ▾」可以取消勾选隐藏不想看的；新加的数组自动出现。

### 外设寄存器
- 左侧下拉选外设（GPIO / TIM / USART…），列表实时刷新寄存器值。
- 右侧改值：输入框填十六进制回车写入；**位域图**直接点格子翻转某一位。
- 选 GPIO 外设时出现 **LED 面板**，点引脚小灯翻转输出电平。

### 内存视图
- 地址栏回车跳转；右侧滚动条拖动可快速跳 ±32KB。
- **点字节格直接改内存**：琥珀色 = 程序改的，绿色 = 你手动改的。

### 调用栈 / 反汇编
- 断点或手动暂停时，调用栈自动显示（栈顶高亮）。
- 反汇编自动定位当前执行位置（▶ 标记）；点汇编行跳回对应源码；编辑器里已编译进固件的行尾有**绿点**标注。

## 常用命令（命令面板搜 "Embedded Debug"）

| 命令 | 用途 |
| --- | --- |
| 编译并烧录 / 烧录现有固件 | 日常烧录 |
| 编译并调试 | 编译 + 启动调试 |
| 附加调试运行中的目标 | 不重编译、不写固件，接管运行中的芯片 |
| 添加到变量监控 | 编辑器右键 |
| 浏览 ELF 变量并添加监控 | 搜索/多选添加 |
| 手动选择芯片型号 | 识别不确定时 |
| 在 STM32CubeMX 中打开 .ioc | 快捷跳转 |

## 常用设置

保存在当前工程的 `.vscode/settings.json`，推荐用命令面板的「**Embedded Debug: 打开设置**」面板修改，一般只需要动这几项：

| 设置 | 什么时候改 |
| --- | --- |
| 工具路径（cmake / ninja / ARM 工具链 / CubeProgrammer） | 环境检测找不到时手动指定 |
| `probeRsChip` | 型号推导不对时手动填（如 `STM32F103C8`） |
| `svdFile` | 外设面板想用指定 SVD 时 |
| `debugRefreshMs` | 觉得面板刷新太慢/太快时（默认 200ms） |
| `downloadSpeedKhz` | 排线长/不稳定时降到 1000 |
| `binFlashAddress` | 烧 BIN 文件时必填（如 `0x08000000`） |

## 使用注意

1. **每次烧录都会弹确认窗口**，这是防误烧设计，请核对工程 / MCU / 探头信息后确认。
2. 烧录前必须**刚编译成功**——编译失败或没编译时烧录会被阻止（防止烧旧固件）。
3. 调试和变量监控需要 **Debug 构建**（带调试信息）；Release 构建启动调试前会提示确认。
4. 变量显示「不在 ELF 中」通常是**被编译器优化掉了**：把优化等级改成 `-O0` / `-Og`，或给变量加 `volatile`。
5. CubeMX 里改了配置 → 重新生成代码 → 回来重新编译即可，插件侧不用动。

## 升级 / 卸载

重装新版 vsix 即可升级，工程设置与监控条目自动保留；扩展面板卸载即移除，不残留系统文件。
